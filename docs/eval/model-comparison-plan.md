# Plan: gpt-4.1-mini vs gpt-6-luna on the 90 typed questions

Written 2026-10-22, **before** any gpt-6-luna answer was seen. The decision criteria below are
fixed now so the comparison cannot be argued after the fact.

## Question

Is `gpt-6-luna` at least as good as `gpt-4.1-mini` for typed questions (Researcher, Router and
Analyst), and does it fix any of the stable misses? Secondary: latency, retries and cost.

## What stays fixed

| | Value |
|---|---|
| Dataset | `typed-questions-90.json`, sha256 `863cbe045b8a…` |
| Match data | the same three hashes as the baseline runs' metadata |
| Prompts | analyst_free@v4, researcher@v3, router@v8 (unchanged; no tuning for the new model) |
| Code | the baseline's `b60e843` plus `46bf538`, which only stops sending `temperature` to GPT-5 / GPT-6 deployments (Luna rejects it). `gpt-4.1-mini` still gets 0.2, so its runs need not be repeated |
| Limits | `max_tokens` 400, 5 Researcher tool calls, the same deadlines; `--max-calls 600` |
| Runs | two complete runs, fresh response cache each, new output files `typed-questions-90-luna-a/b.jsonl` |

One unavoidable difference: Luna samples at its own fixed setting instead of temperature 0.2.

## How it is scored

- The same rubric as the baseline: answerable cases on relevance and grounding (headlines
  included); behaviour cases as correct / weak / wrong. Same scorer (Claude), same reference
  facts. Luna is scored **before** looking at the per-case baseline table, then compared.
- Scores go into the same `model-comparison-scores.json` under the Luna run names;
  `compare_runs.py` regenerates the metrics for all four runs.
- Codex is asked to audit a sample, at least every case where the two models disagree.

## What is compared

1. **Hand scores**: each total above, per run and mean.
2. **Per-case flips**: cases that pass in both baseline runs but fail with Luna (regressions),
   and cases that fail in a baseline run but pass in both Luna runs (fixes).
3. **Automatic**: model calls, latency, Analyst first-attempt rate, template fallbacks,
   verifier rejections by check (length, katakana club names and role placeholders in
   particular), Researcher fallbacks (timeout, error, malformed).
4. **Output style**: answer length, truncated or empty replies (a reasoning model may spend
   part of the 400-token budget before it answers), Japanese quality on the 16 JA cases.
5. **Cost**: model calls × list price per token. Tokens are not logged yet, so this is an
   estimate.

## Decision criteria (fixed in advance)

Switch the live app to `gpt-6-luna` only if **all** hold, averaged over the two Luna runs:

1. Relevant answer or correct behaviour **≥ 81 / 90** (the baseline mean minus 1).
2. Behaviour cases wrong **≤ 2.5** per run (no worse than the baseline).
3. **No new false claim**: no case that passed in both baseline runs gets an answer asserting a
   false fact or an invented identity in either Luna run.
4. Clarifications (a01–a03), injections (h01–h03, mix01–02, j05) and out-of-scope declines
   (o01–o04) all hold in both runs.
5. Latency p90 **≤ 12 s**, and no reply truncated by the token limit.

If any fails, the live app stays on `gpt-4.1-mini` and the comparison is reported as is. If Luna
wins but needs a prompt change, that is a separate measured step, not part of this comparison.

## Out of scope

- The overlay-card narrations of the live match were written by `gpt-4.1-mini` and replayed. A
  switch would regenerate them as a separate step, with the card verifier rerun. The 99.3 %
  catch rate does not depend on the model: it mutates template narrations.
- The live switch itself (the Container App's `AZURE_AI_MODEL_DEPLOYMENT_NAME`) is its own
  cloud step with the owner's go.

## Steps

1. Done: `gpt-6-luna` deployed (GlobalStandard, 50K TPM) and smoke-tested; temperature fix
   committed (`46bf538`).
2. Two Luna runs of the 90 (about 600 calls, roughly ¥25–30 at Luna prices). Owner's go needed.
3. Score, compare, write `model-comparison-results.md`, update the README.
4. Only if the criteria hold: the live switch, with the owner's go.
